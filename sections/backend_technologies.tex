
\subsection{ASP.NET Core}
\paragraph{}ASP.NET Core \cite{aspnetcore} is a high-performance, open-source framework engineered for building modern, cloud-based, and cross-platform applications. Serving as the evolution of the traditional ASP.NET framework, it introduces a modular architecture that emphasizes speed, scalability, and developer productivity.

Our selection of ASP.NET Core was driven by the following factors:
\begin{itemize}
\item \textbf{Skill Acquisition}: We identified this framework as an ideal opportunity to expand our technical repertoire. Although not part of our formal curriculum, its widespread industry adoption presented a compelling challenge for professional growth.
\item \textbf{Career Alignment}: Given its significant market share within enterprise environments, mastering the Microsoft ecosystem provides a strategic advantage for our future career prospects.
\item \textbf{High-Performance Runtime}: The framework's lightweight, modular design ensures optimal execution speed.
\item \textbf{Cross-Platform Versatility}: Its ability to operate seamlessly across Windows, Linux, and macOS offers us the deployment flexibility necessary for diverse infrastructure requirements.
\end{itemize}

\subsection{Entity Framework Core}
\paragraph{}Entity Framework Core (EF Core) \cite{entityframeworkcore} is the lightweight and extensible object-relational mapper (ORM) for .NET. It simplifies data access by allowing developers to interact with the underlying database using strongly-typed C\# objects. By abstracting raw SQL queries, EF Core promotes cleaner, maintainable code while providing a robust interface for complex database operations.

\subsection{BCrypt.Net-Next}
\paragraph{}BCrypt.Net-Next \cite{bcrypt} is a high-performance security library used for robust password and token hashing. Unlike standard hashing algorithms, BCrypt incorporates a dynamic \textit{salt} mechanism, which adds a unique, random string to each piece of data before the hashing process. This creates a powerful defense against rainbow table attacks and credential exposure.

In our implementation, we utilize this library to secure both user passwords and sensitive tokens. By enforcing a cost factor, BCrypt ensures that the hashing process is computationally expensive, making it significantly harder for attackers to perform brute-force attempts. This integration is central to our security layer, ensuring that even in the event of a database compromise, all sensitive information remains protected by cryptographic best practices.


\subsection{Profanity Detector}
\paragraph{}The Profanity Detector \cite{profanitydetector} is a lightweight utility library integrated into our backend to ensure a family-friendly environment for all users. By maintaining an extensive, pre-defined dictionary of offensive terms, it allows for real-time validation of user-generated content before it is persisted in the database.

In our implementation, this library acts as a content moderation layer, automatically scanning messages and profile information for inappropriate language. This approach shifts the responsibility of content filtering from manual human moderation to an automated system, ensuring that the platform remains professional and compliant with community standards without introducing significant latency to user interactions.

\subsection{Mapster}
\paragraph{}Mapster is a high-performance mapping library specifically designed for .NET ecosystems \cite{mapster}. It offers an optimized solution for object-to-object transformation, effectively eliminating the need for boilerplate mapping logic.

We selected Mapster as our primary mapping solution due to its clear technical advantages over alternatives like AutoMapper:
\begin{itemize}
\item \textbf{Superior Performance}: Mapster delivers execution speeds approximately four times faster than comparable libraries.
\item \textbf{Low-Maintenance Configuration}: It requires significantly less setup, allowing for a more streamlined development process.
\end{itemize}

Within our application, Mapster is essential for decoupling our domain models from the Data Transfer Objects (DTOs) exposed through our API controllers. By centralizing these transformations, we avoid the maintenance burden of repetitive, manual code.

As demonstrated in our implementation, the transformation of domain entities into response models—such as the \texttt{CompanyOutputModel}—is performed concisely throughout all API controllers:

\begin{lstlisting}[caption={Concise domain-to-DTO transformation}, label={lst:mapster-controller}]
// Mapping a single entity to a response model
return res.Match(
success => Ok(success.Adapt(<CompanyOutputModel>)),
error => error switch { /* ... */ }
);

// Mapping a collection of items during search
Items = success.Items.Adapt<List>(),
\end{lstlisting}

This pattern is consistently applied across every controller in our API, ensuring that our responses remain clean, consistent, and strictly decoupled from the internal domain model structure. While we occasionally use manual LINQ projections for highly specialized data requirements, Mapster serves as our standard approach for the vast majority of data transformations, significantly improving our codebase's maintainability.</List

\subsection{MailKit}
\paragraph{}MailKit is an open-source cross-platform .NET library for SMTP, POP3, and IMAP. It provides a simple way to handle email functionality within .NET applications \cite{mailkit}.

In our Hubly application, MailKit is important for enhancing security and user verification when a user tries to register on the app it will send a confirmation email to the user's email address. The implementation leverages MailKit's SmtpClient to connect to our email account, authenticate, and send the confirmation code to the user's email address.

This automated email verification system is essential for maintaining the security of our application, preventing fraudulent accounts, and ensuring that all users have valid contact information in the system.

\subsection{XUnit}

\paragraph{}XUnit is a widely used testing framework for .NET applications\cite{xunit} providing simplicity and extensibility. Unlike older testing frameworks, XUnit uses attributes instead of base classes, enabling more flexible test organization and execution.

Our testing strategy implemented a multi-layered approach, using the Xunit Fixture pattern\cite{xunitFixture}:
\begin{itemize}
  \item \textbf{Unit Tests}: We developed targeted tests for the Service Layer, isolating business logic from external dependencies through mocking. This approach allowed us to verify business rules and service behaviors independently of infrastructure concerns.
  
  \item \textbf{Integration Tests}: For the Repository Layer, we created integration tests that verified our data access code against a real database environment. These tests ensured that our Entity Framework queries and database operations functioned correctly with the actual PostgreSQL schema.
\end{itemize}

For integration testing, we used Testcontainers\cite{testcontainers}, a library that programmatically manages Docker containers. This allowed us to:
\begin{itemize}
  \item Automatically create isolated PostgreSQL containers for each test class
  \item Pre-populate databases with controlled test data through our seeding methods
  \item Execute tests within a real database environment without affecting development or production databases
  \item Ensure consistent test results regardless of the development environment
\end{itemize}
