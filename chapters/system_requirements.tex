\chapter{System requirements}\label{ch:system_requirements}


\paragraph{}This chapter presents the main requirements defined for Hubly. The requirements are divided into functional requirements, which describe the features that the system must provide, and non-functional requirements, which describe quality attributes expected from the system.

\section{Functional Requirements}
\paragraph{}The functional requirements of Hubly are listed below, focusing on the main operations that the system must support:

\begin{itemize}
    \item Users to register and authenticate.

    \item Require email confirmation before users can access the main features of the application.

    \item Allow each user to complete their profile either as a company or as a creator.
    
    \item Allow companies to create and manage a company profile, including information such as name, description, sectors, company size, website and country headquarters.
    
    \item Allow creators to create and manage a creator profile.

    \item Allow creators to create and manage multiple social profiles, each associated with a specific platform, such as Instagram, YouTube, TikTok and more.
    
    \item Each creator social profile must store information relevant to discovery, such as platform, username, link, description, audience size, content sectors and price range.
    
    \item Provide a shared sector classification mechanism, allowing companies and creator social profiles to be associated with one or more sectors.
    
    \item Allow companies to search for creator social profiles using filters such as platform, sector, audience size and price range.

    \item Allow creators to search for companies using filters such as name, sector, company size and country headquarters.

    \item Allow users to view company profiles and creator social profiles.
    
    \item Record profile views, allowing previous interactions to be used by other system features.
    
    \item Allow users to initiate conversations associated with the relevant company or creator social profile.
    
    \item Support message exchange between participants in a conversation.
    
    \item Support message state management, including read status, edited messages and deleted messages.
    
    \item Allow users to create private conversation tags.
    
    \item Allow users to assign private tags to conversations, without making those tags visible to the other participant.

    \item Allow users to rate creators after an interaction.

    \item Maintain creator rating information based on received ratings.

    \item Support account verification status for companies and creators.

    \item Support availability status for creators.

    \item Provide recommendations of companies or creator social profiles based on previous user interactions, such as searches and profile views.

\end{itemize}

\section{Non-Functional Requirements}
\paragraph{}The non-functional requirements of Hubly are listed below, focusing on the quality attributes that the system should exhibit:

\begin{itemize}
    \item \textbf{Security}: Must restrict access to authenticated users and require email confirmation before allowing access to the main application features.

    \item \textbf{Data protection}: Must avoid storing passwords in plain text and must use secure password hashing + salt mechanisms.

    \item \textbf{Access control}: Must validate the authenticated user before executing protected operations.

    \item \textbf{Data consistency}: Must preserve data consistency during operations that involve multiple persistence steps, such as registration, email confirmation and profile management.

    \item \textbf{Maintainability}: Should be organized into separate components and layers, allowing each part of the application to be modified or extended with limited impact on the rest of the system.

    \item \textbf{Modularity}: Should separate concerns between user interface, application logic and data persistence.

    \item \textbf{Usability}: Should provide clear flows for registration, profile creation, search, conversation management and negotiation tracking.

    \item \textbf{Performance}: Should support filtered and paginated searches, avoiding unnecessary data loading when users search for companies or creator social profiles.

    \item \textbf{Portability}: Should be deployable in a containerized environment, reducing dependency on a specific local configuration.

    \item \textbf{Testability}: Should support unit and integration testing, particularly for backend services, repositories and business rules.

    \item \textbf{Reliability}: Should handle errors in a consistent way, returning structured responses when operations fail.
\end{itemize}
